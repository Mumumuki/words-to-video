# 第十二步｜故事板视觉方向卡

- 项目：
- 版本：SB-STYLE-v3.0
- 用途：定义本片故事板的视觉与排版规范（第十二步 b 段），独立于资产图展示规范，但不与项目定稿风格卡冲突。
- 相邻环节：a 段关键帧画面提示词打磨见 `templates/storyboard-prompt-craft.md`；c 段出图自检见 `templates/storyboard-selfcheck.md`。
- **版式策略**：每段**必出两版式**，用途不同、不可互相替代——**展示版 `table`（给人看）**与**模型版 `raw`（给视频模型）**各一张独立整图。
- **出图方式**：两版均**改为脚本合成**。展示版必出 N 张无字单格画面（`cells/`，默认 6），脚本负责题头、资产带、分镜网格、材质区、技术区与全部文字；模型版由同一批 cells 拼成。**「模型一次生整图」在展示版上退役**，仅作应急备选（见第二节末尾）。格序统一 `grid_of(N)`（6 格时为 `R1C1→R2C3`）。配色按风格卡 palette 上色（见 `templates/style-palette.md`）。

## 一、视觉方向

| 维度 | 内容 |
|---|---|
| 画面形式 | **彩色写实**，呈现接近成片的画面效果，不是黑白线稿 |
| 风格来源 | 严格沿用项目定稿风格卡（SB-STYLE 只做投影，不另立风格） |
| 媒介与质感 | 与风格卡一致：媒介、颗粒、锐度、景深按风格卡执行 |
| 色彩 | 沿用风格卡的色彩体系与冷暖倾向，不另调色 |
| 光线 | 按每镜已确认的运镜与光位执行，不用资产图的影棚均匀光 |
| 背景 | 场景画面依 `场景01-V01/V02` 的空间结构，不回到空白背景（不填纯白/无内容） |
| 禁止 | 黑白线稿、草图笔触、色块示意、插画化、风格偏移到其他美术方向 |

> 与资产图的区别：角色图、道具图是风格浅色底影棚展示；故事板是成片画面。两者同源（同一风格卡、同一造型编号），但呈现方式不同，不得混用。

## 二、版式策略（每段必出两版式）

每一段落 `P0N` 对应**一套**故事板 `SB-0N`，一套必出**两版式**两张独立整图，分别服务两类读者：

- **展示版 `table`（给人看）**：**六区段落板**，2400×2960（约 4:5，A4 竖版恰好一页）。六区回答六个问题——这一段有谁、在哪、几人怎么站、每格演什么、光从哪来、什么规格。受众是非专业者（客户、观众、合作方），不必懂景别运镜也能读懂，也能按「第④区第 3 格」这样的编号互相指认。
- **模型版 `raw`（给视频模型）**：2 行×3 列（6 格时），2352×高随格数扩展，**每格严格 16:9、全图零文字**。用途是被裁成 N 张单帧，直接作图生视频的首帧。

两版装同一组 6 关键帧、格序通用 `R1C1→R2C3`。

> **记法先统一，免得两版被当成两种网格**：全文里的「2×3」「3 列 × 2 行」「2 行 × 3 列」都是**同一种网格**——6 格时即 3 列、2 行，读序 R1C1→R1C2→R1C3→R2C1→R2C2→R2C3；格数变化时以 `grid_of(N)` 重新排布（2–3 格单行、4 格 2×2、5–6 格 3×2），读序一律从 R1C1 起逐行。`table` 的 ④ 区与 `raw` 整版用的是同一套格位，第 i 格对第 i 格，不允许出现"展示版 3×2、模型版 2×3"这种说法。

| 版式 | 名称 | 画幅 | 结构 | 用途 |
|---|---|---|---|---|
| `table` | 展示版（必出） | 2400×高随格数扩展（6 格时 2960） | 六区纵向递进：题头 / ①②③ 三栏 / ④ 分镜 `grid_of(N)` / ⑤⑥ 两栏 / 页脚 | 交付文档主图、导演执行、汇报 |
| `raw` | 模型版（必出） | 默认 2352×1000（6 格时，≈2.35:1；格数变化则高随格数扩展） | `grid_of(N)` 网格，每格严格 16:9，无任何文字 | 裁 N 张单帧喂图生视频；整张作分镜参考 |

### 为什么展示版必须走脚本合成

展示版全版约 200 字以上、四层字号、五个信息带。模型一次生整图的实测问题是：文字必错（「特写」误作「特景」是记录在案的例子），且网格对齐不可控、格子之间会连成一片。字数越多，出错后「整版重出」的代价越高。

改由脚本绘制后，文字零乱码、几何精确、改一处不会牵连全张。**代价只有一条**：6 格画面分 6 次生成，需靠风格卡前缀、固定资产编号、统一光位描述压住「六张画风各异」的风险。

**应急备选（非主流程）**：客户只要一张示意、明确不要 cells 时，可退回模型一次生整图，并在交付中注明「文字可能有误，不作交付主图」。

> **为什么模型版必须零文字**：图生视频模型把输入图整张当作一帧，画面里任何序号、标注带、页眉都会被一起生成进视频。`raw` 因此是唯一要求「画面区零文字」的版式——这不是省事，是硬要求。
>
> **为什么模型版每格必须严格 16:9**：裁出的单帧要直接当首帧用；比例不对就得二次补边或裁切，等于白做一遍。
>
> **两版不可合并**：把文字加到 `raw` 会污染喂给模型的画面；把 `raw` 当交付主图，读者又读不到任何信息。

| 间隔 | — | 44 | — |
| ① 出场人物+道具 / ② 对手戏场景 / ③ 空间调度 | 244–964 | 720 | 640 / 900 / 636，之间 40 与 80 虚线分隔 |
| 间隔 | — | 40 | — |
| ④ 区标题行 | 1004–1104 | 100 | 左：区号＋「分镜关键帧」；右：段落号·段名·时间码 |
| ④ 分镜网格 | 1104–2384（6 格时） | 1280（6 格时） | 3 列 × 2 行（6 格时），格 725×620，行距 40；格数变化时按 `grid_of(N)` 重排 |
| 间隔 | — | 56 | — |

## 四、逐区内容规范

六区是**纵向递进**关系：由设定（谁、在哪、怎么站）到执行（每格演什么）再到参数（光、规格）。横版并排会把 ④ 挤扁，因此不做横版。

### ① 出场人物 + 登场道具

- **人数自适应**，脚本按 `cast` 长度自动换排法，不许手工挑版式：

| 人数 | 排法 | 人像尺寸 | 道具 |
|---|---|---|---|
| 1 人 | 半身大图 + 右侧说明（姓名／编号／作用短语至多四行） | 210×330 | 配图，145 见方 |
| 2 人 | 等高半身像并排，各自带姓名三行 | 约 309×270 | **退成一行文字**，让位给人物 |
| 3 人 | 同上，三等分 | 约 198×270 | 同上 |
| 0 人 | 「本段无出场人物」 | — | 按实际 |

- **半身取图**：`cast[].crop` 缺省取角色卡**上半区左侧主视觉区**（`[0.02,0.08,0.26,0.615]`，本身就是头顶到腰胯；y1 必须停在 0.628 的分割线之前，取 0.66 会把分割线与下半区信息表首行带进来），**取完不再二次裁切**——旧版取完再切 56%，落到胸口，与「自头顶取到腰胯」不符。单人不用全身图，是因为角色卡里根本没有可用的全身像：三视图那三张脸已被灰圆盖住。
- **为什么一律半身**：640 宽的栏里并排三人，全身像只有 120 宽、脸约 28px，缩到纸上是 2 毫米，认不出是谁；半身改到脸约 60px，且 2 人与 3 人的人像尺寸完全一致，不会出现「人多的段落人就变小」。单人同样按半身处理，全片人物呈现口径统一。
- **A/B/C 圆标**：多人时每个姓名前带圆标，取值来自 ③ 区 `blocking.actors.tag`，按 name 或 id 匹配，对不上才按出场顺序给。**这不是装饰**：③ 区俯视图上的 A/B 方位点必须能对回具体的人，否则调度图上的 A/B 是悬空的。
- **透明底**：人物与道具一律白底去背后贴入，不加白底方块框。去背只删「与画布四边连通的近白区域」，人物自身的白袍、白发、白袖被身体包围、不与边缘连通，因此完整保留。全身站姿补一道模糊椭圆接触阴影（「立在纸上」）；**半身像不补阴影**（腰胯断面加地面阴影会像悬空）。
- 本段作用一行短语（「主位 · 六镜全程在场」），不写完整设定——完整设定在第一部分角色卡，这里只做就近索引。

### ② 对手戏场景

- 用人眼全景单图（`场景01-V02`），**不用微缩全景 V01**：这一段观众就站在这个位置看。
- 图下写场景编号（必须到视角子编号）、名称、一句取景说明（机位在轴线哪一侧、视高多少、看什么）。
- **一个段落只对应一个场景**：② 区只放 `set` 指定的那一个视角，③ 区调度图也只按该场景绘制。段落跨两个场景时，换景在 cells 上体现（格画面本身换景），不改数据 JSON 结构。

### ③ 空间调度

- **单人静态段照画，只省关系线**：只要数据里有 `blocking.actors` 就出图——场地框、人位、机位方块、比例尺、指北针都保留（机位是后续轴线一致性的凭据），没有 `relations` 时不画视线/位移/轴线。**不要退回「本段单人静态，无需调度图」的占位文字**：那会把 ③ 区整块留白，反而看不出机位在哪一侧。六区是「最多六区」，不是「每段必六区」，但只要有站位数据就该画。
- 由脚本绘制，不由模型生成：矩形场地 + A/B 方位点 + 视线／轴线虚线 + 机位方块＋虚线与「机位」标注 + 比例尺（默认取 `blocking.w`）+ 指北。模型画平面图常画成透视图或比例失真。
- 数据只需每个角色一个 0–1 相对坐标和一句关系描述。同一对角色同时给了视线与轴线时脚本去重，不叠画两条。

### ④ 分镜关键帧

- 3 列 × 2 行（6 格时，格数变化时按 `grid_of(N)` 重排），格 725×620，画面区 725×408 严格 16:9。
- 画面角标：**编号左上、时间码右上**，白字深描边——压在任何明暗画面上都能读。
- 信息区四层，自上而下：
  1. `镜号 · 景别 · 时长`（左）＋ `情绪`（右，点缀色）
  2. 内容描述，最多 2 行，写「谁·在做什么·环境怎样」，不写景别运镜
  3. 台词原文，**宋体艺术字**（与描述区分开），无台词不占行
  4. `音效 · 运镜`，小字退后

### ⑤ 光影与材质

- 从 ④ 的六格里**裁局部**（衣角、手、地面、灯火、窗棂），零生成成本；也可由 `materials[].img` 指定独立图。
- 每块配标签＋一句说明（「窗棂切光 · 冷 5600K」）。四块横排。

### ⑥ 摄影与技术说明

- 收成**两列圆点列表**，八到十项：画幅、镜头焦段、光圈、帧率、色温、调色、光位、声音、景深、剪辑。
- 全部从 S4/S5/S7 已有字段汇总，不新增信息。

## 五、文字与标注规范

> **`raw` 模型版全图零文字**：不写序号、不写标注、不设页眉页脚；画面区内除画面本身外不得有任何元素。本节以下规则仅适用于 `table` 展示版。

### 文字位置（硬约束，仅 `table`）

- 展示版每段文字都在自己的区域内，**一律不压在画面之上**，唯一例外是 ④ 的编号与时间码角标（白字深描边，为跨明暗可读）。
- ④ 缩略画面区**不叠加任何其他文字、序号、色块、水印、logo**。序号已在角标位，画面里再叠一遍属重复。
- 除既有文字外，不添加装饰线、水印、logo。**平台生成图自带的水印脚本去不掉，正式用图需裁切或重生。**

### 字体与层级

| 用途 | 处理 |
|---|---|
| 篇名、姓名、台词 | 艺术字（按风格卡世界美学取向选字体） |
| 区标题 | 区号圆标 + 中文大号 + 英文小字（双语开关见下） |
| 正文 | 常规字体，按信息层级分 `--ink` / `--ink2` / `--ink3` / `--ink4` 四级 |
| 区号、情节号 | 点缀色圆标／大号渐变字 |

- **双语标签**：由风格卡的世界美学取向决定开关。架空／现代／科幻可留英文（`CHARACTER`／`BLOCKING`），唐宋明等古典题材只留中文加一道短横线，避免工业制片语言破坏古风。
- **中文断行**要有行首标点规则（不把「，。、）」留在行首），且数字带单位不得拆开——`30°` 不能断成「3」和「0°」。

### 资产图的前置要求（决定能否去背）

① 区的人物与道具做去背，**前提是图里主体周围是纯色背景**：

- **背景单一纯色**——纯白最佳，风格浅色底亦可；脚本的判据是「四角颜色散度」而非「必须是白」，浅色底同样能去干净。不可为渐变底、无投影、无边框。
- **主体周围留出至少 5% 空白**，不要顶到画布边缘，否则去背无从下手。
- **画面内不要有标题文字**：深色文字不与背景连通、去背时会被保留（实测原图左上角「人物：角色01-造型A」被整行留下），只能靠 `crop` 切掉。

**带分区与信息表的资产卡不能整张去背**：6:5 角色卡下半部是信息表，5:6 道具卡四宫格各有标签与说明条，整张去背都会把文字一起留下。`cast[].crop` 缺省即裁到角色卡**上半区左侧主视觉区**（约 `[0.02, 0.08, 0.26, 0.615]`，生图后按实际微调），只取人像本身，**取完不再二次裁切**；道具同理，`props[].crop` 收在**正面格**内（1500×1800 卡面上正面格约 `x 30–742, y 140–852`，上方让开格内标签、下方让开格框与说明条，取 `[0.05, 0.12, 0.485, 0.468]`，生图后按实际微调）；场景同理，`set.crop` 收在**左下格 V02**（1800×1500 卡面上 V02 约 `x 24–1144, y 784–1402`，让开左上标签后取 `[0.03, 0.558, 0.63, 0.93]`）——不写就按这三组缺省值走。裁完再交给脚本去背。外部上传的单张全身人像请显式给 `crop`（`[0,0,1,1]` 表示整张），否则会被缺省值当成角色卡切掉大半。

原图不是纯色底时脚本自动放弃去背，退回带框裁切，不会出空白格（判据：四角颜色散度 > 12、或边框近底色比例 < 55%）。

## 六、版面配色（取自风格卡 palette，全项目一致）

所有外壳配色来自 `templates/style-palette.md`，不写死黑白灰。具体 hex 由每个项目 S5 定稿后的风格卡填入。

| 用途 | palette 变量 | 说明 |
|---|---|---|
| 整板底 | --base（主色浅派生） | 非纯白，风格浅色底 |
| 题头带 | --ink（深色通栏） | 全页最重的一块，让图在文档里立刻分开 |
| ①②③ 带底 / 降级占位 | --band | 三栏底 |
| 区号圆标 / 强调 | --accent（点缀色） | 区号、A 点、情绪、编号下划线 |
| 分隔虚线 / 细框 | --sep / --rule | 三栏之间、画面收边 |
| 主文字 | --ink | 标题、姓名、台词 |
| 次文字 | --ink2 | 描述、场景名 |
| 弱文字 | --ink3 / --ink4 | 作用短语、音效运镜、英文标签 |

> `raw` 模型版只用 --base 作底色与格间安全边，**不使用**任何文字与装饰色——它没有文字，也就没有这些角色。

> **与资产卡的线宽差异是刻意保留的**：资产卡顶栏用 **2px 重分隔线**（封面级视觉锚点），故事板页眉用 **1px 细线**（避免与格框抢视觉）。两者是不同载体的设计取舍，**不视为不一致，后续不要互相"统一"**。

## 七、资产与编号引用

- 沿用 `角色01-造型A`、`场景01-V01`～`V06`、`道具01` 等既有编号，不重新命名。
- 场景必须写到视角子编号；依据哪个视角构图，就在该格画面中体现，并在映射表记录。
- 同一格内出现的角色，其造型必须是第四步造型清单中已登记的编号；不得出现未登记造型。
- 只使用已确认的角色图、道具图、场景图作参考，不以参考图缺失为由改变已确认的构图决策。
- 脚本按编号在 `--assets` 目录自动找图：`character-<id>*.png` / `scene-<id>*.png` / `prop-<id>*.png`。**场景卡的文件名用场景主编号**（`scene-场景01.png`）——数据里 `set.id` 写的是视角子编号（`场景01-V02`），脚本找不到精确匹配时会自动回退到主编号再找一次。仍找不到才降级为占位，并在 stderr 打一条告警（不再静默降级）。

## 八、一致性重点

下列情形在生成前必须逐格核对，防止故事板中出现跳变：

| 情形 | 核对要点 |
|---|---|
| 远景 → 中景 → 近景连续推近 | 主体占比逐格放大，透视压缩程度递增，背景可见范围递减，不得跳格 |
| 环绕镜头起点／过程／终点 | 三格处于同一空间，背景物体随视角合理位移，不得背景重置 |
| 过肩镜头 | 前景肩部与后景人物比例、相对位置、焦点归属合理，前景不得消失或换人 |
| 正反打 | 轴线一致，两人视线互相指向，两面背景保持可解释的对应 |
| 同一运镜段落内各格 | 同一空间、同一造型编号、同一光线逻辑 |
| **六格分次生成** | 风格卡前缀一致、资产编号一致、光位描述一致，不得出现六张画风各异的图 |

> 出图后还要按 `templates/storyboard-selfcheck.md` 逐项复核：几何项用 `scripts/verify_storyboard.py --layout table|raw` 量测，不靠目测；视觉项逐格对照。

## 九、修改边界

- 修改故事板视觉或排版：只修订本卡并重出故事板，不动分镜与资产图。
- 修改机位、运镜、关键帧结构：回退第七步分镜，不在故事板内调整。
- 修改项目资产视觉风格：回退第五步，不在本卡改动。
- 修改角色造型：回退第四步造型清单，不在故事板内临时新增造型。
- 资产图不满足纯白底而无法去背：回退 S9/S10 重出资产图，不在本卡放宽去背要求。
