# 第十三步｜Word 交付文档结构规范

- 项目：
- 版本：DELIVERY-v5
- 文档格式：`.docx`
- 生成方式：使用文档创作能力生成，不手工拼 HTML

> 本文档是最终交付物。它有两个读者：想读懂故事的人看第一部分，想照着执行的人看第二部分。两部分不混排。

## 文档总结构

```
封面页
第一部分｜剧本总览          ← 可读，无时间码、无镜头编号
第二部分｜分镜执行          ← 可执行，按段落分块，图文对应，可直接进工作流
```

# 封面页

- 篇名（主标题）
- 副标题：分镜执行文档
- 来源信息：改编填「作者 · 朝代或年代 · 体裁」；原创填「原创 · 项目定义」
- 目标时长 / 视频内容类型 / 段落数（= 故事板套数）/ 故事板图张数（套数 × 2）
- 定稿风格卡 ID 与版本
- 版本号与日期

# 第一部分｜剧本总览

> 本部分只讲故事，不讲技术。禁止出现时间码、镜头编号、景别、运镜术语。

## 1.1 来源与项目定义

按来源形态二选一，不并存：

**改编（`adaptation` / `hybrid`）**

- 篇名、作者、朝代或年代、体裁
- 来源全文，以引用块或独立段落呈现，不与解读混排
- 必须保留项清单（逐条列出本片没有改动的原作事实）

**原创（`original`）**

- 项目名、logline
- 来源类型（一句话／梗概／大纲）与用户原话
- 世界前提：三到五句，交代这个故事发生在什么规则之下
- 本片刻意采用与刻意避开的方向各一条

## 1.2 情节总览

3–5 段连贯叙述：故事从何处起、经过什么、落点在哪。不分场次、不标注秒数。

## 1.3 世界与故事背景

时代或世界规则、地域、社会情境、人物所处的生活状态。涉及推断处标 `[推断]`，创作补全标 `[创作]`。科幻项目须写明关键的科技等级与代价，现代项目写明制度与生活条件。

## 1.4 主要角色

每个角色一个小节：

- **角色01｜姓名**
- 身份、年龄、外形要点、性格、在本片中的行为逻辑
- 造型说明：本片共几套造型，各在哪些场次出现，变化原因
- **配图**：该角色每个造型各一张 **6:5 角色卡**（原尺寸，五区整卡：顶栏约 7%／上半区约 60%（半身主视觉＋三视图）／下半区约 33%（六行信息表＋四格细节特写）），图下注明「角色01-造型A｜出场：S01、S02」

> 第一部分统一用**资产卡**（角色卡／场景卡／道具卡），自带项目元信息、适合阅读；第二部分用该**资产卡（或故事板源图）**作提示词参考。两者同源同编号，不是两套素材。

## 1.5 故事发生的场次与场景

每场一个小节：

- **场次 S01｜地点｜时间｜天气**
- 空间性质、关键陈设与位置、光线条件、人物活动范围
- **配图**：该场景一张 **6:5 场景卡**（原尺寸，左二右四：左列 V01 微缩全景＋V02 人眼视角，右列远景1–4 ＝ V03–V06 四张取景），图下注明「场景01｜V01–V06｜出场：S01」

## 1.6 关键道具

只列第四步判定为「出图」的道具；判定为「仅文字」的道具不单列，随 1.5 的文字说明带过即可。

- **道具01｜名称**
- 形制、材质、尺寸、使用痕迹、在剧情中的作用
- **配图**：该道具一张 **5:6 道具卡**（原尺寸，2×2 四宫格：正面／侧面／背面／入戏画面），图下注明「道具01｜关联：角色01-造型A／场景01-V02」

## 1.7 风格统一基调

- 六维风格卡摘要（媒介、世界美学、影像质感、色彩、光线、参考锚点）
- 统一负面词
- 一句话定调：这部片子的画面应该是什么感觉

# 第二部分｜分镜执行

> 按段落 `P01`、`P02`……顺序排列。每段自包含：单独抽出这一段，连同本段用图，就能直接粘进 ComfyUI 的文本节点执行。
>
> 本部分的提示词是**第八步 H3 六段式原文**，不重写、不缩写、不另起一版。文档只负责把它排版清楚、配好图。

## 单段结构（每段都按此模板）

### 段标题

`段落 P01｜00:00.000–00:15.000｜时长 15s｜故事板 SB-01`

### 一、本段剧情推进

2–4 句，说明这一段在整条故事线里推进了哪一步、从上段哪里接上、落到什么状态。

### 二、本段用图（Picture 编号 ↔ 资产编号）

> `Picture N` 是提示词里唯一使用的图引用编号，**整集统一，不逐段重排**。资产编号保留在表里做追溯，一个字不改。只列本段实际挂载的图，未挂的槽位不写。

| 槽位 | 资产编号 | 用途 | 文件 |
|---|---|---|---|
| Picture 1 | 角色01-造型A | 男主外型 | `Picture1_角色01-造型A.png` |
| Picture 3 | 场景01 | 空间全景 | `Picture3_场景01.png` |

- 资产图在本节插入（压缩版，长边 1600px），图注写 `Picture N｜资产编号｜用途`。
- 一段内挂载不超过 5 张，超出时按“说话人 ＞ 目标人物 ＞ 场景 ＞ 被使用的道具”取舍。
- 表后紧跟一句引用话术，供整段复用：

```text
Role and location references are <Picture 1> and <Picture 3>.
```

> Picture 编号与资产编号必须一一对应：不得出现提示词里引用了、表里却没有的槽位（悬空引用），也不得让一个槽位指向两个资产。

### 三、本段参数

| 项 | 值 |
|---|---|
| 本段时长 | 15s |
| 成片画幅 | 16:9（按 S0 项目定义的锁定值填；默认 16:9） |
| 分辨率 | 1920×1080 |
| seed | （首次试跑固定值） |
| 节点时长 | 10–15 秒（按节点实际设置填；若锁死 10 秒，本段须按 10 秒重划，不拆份） |
| 上一段 | `—`（首段）／ `P00` |
| 承接帧 | `handoff/P00-last.png` → 本段 `handoff/P01-first.png`；`<Continuity>` 已写 |

> **画幅不是随手可改的字段。** 故事板 `cells` 与 `raw` 每格按 16:9 定几何（`raw` 默认 2352×高随格数扩展、`table` ④ 每格 725×408），这 N 张 cells 同时是图生视频首帧。成片若要竖屏，必须在 S0 就定，并同步改 `build_storyboard.py` 的网格常量与 cells 出图尺寸——只改这里的分辨率，首帧与成片比例会不符。详见 `references/platforms/comfyui-minimax.md` 第一节。

> 视觉基调不在这里重复——它已经写在提示词 `detailed_description` 的第一句里。在文档里另写一份，复制时容易漏掉其中一处。

### 四、本段提示词（H3 六段式 · 整段可复制）

**一份完整的 `prompt.txt`，六个字段齐全、顺序正确。** 整块复制进 ComfyUI 文本节点，不拆、不删、不改写。

| 字段 | 这一份里写什么 |
|---|---|
| `subject_definitions` | 每个角色/场景一个 `<Subject N>`：服装拆到部件＋`LOCKED`＋`EXPLICITLY NOT`，位置锁定，音色与说话人 ID，末尾写 Picture 绑定 |
| `summary` | `[reference generation]` 前缀 ＋ 全部锁定重申 ＋ 逐镜概括（含台词字数与语速） |
| `retention_analysis` | 一人一行、一场景一行，写清保留与替换；**最后一行 `<Continuity>`** 声明接续上一段哪一帧（首段写 `none`）；服饰与位置**完整重申，不写"同前"** |
| `detailed_description` | 风格句 → 曝光统一前缀 → 锁定重申 → 逐镜 `[Shot N] At MM:SS.mmm` 描写 |
| `overall_soundscape` | 按镜头顺序的环境音与拟音，写具体声源与位置 |
| `non_diegetic_music` | `N/A` |

标准格式（照抄结构，内容按本段事实填）：

```text
subject_definitions:
<Subject 1> is [姓名] — FACE from <Picture 1> (...). OUTFIT LOCKED as (...). POSITION LOCKED: (...). VOICE: (...). (S1)
<Subject 3> is the [场景名] in <Picture 3>: (...)
<Picture 1> ref <Subject 1>'s face. <Picture 3> ref <Subject 3>.

summary:
[reference generation] 15s [段落标题]. (...) LOCKED: (...). 0-3s: (...). 3-8s: (...)

retention_analysis:
<Subject 1> (appears in Shot 2, Shot 3): fully_preserved - ...
<Subject 3> (all shots): fully_preserved - ...
<Picture 1-3>: fully_preserved.

detailed_description:
The target video is in (...) style. Visual characteristics: (...)
Exposure unified across all shots — mid-grey baseline, shadows retain detail, no shot darker or greener than another.
[姓名] OUTFIT LOCKED THROUGHOUT: (...). EXPLICITLY NOT (...).
[Shot 1] At 00:00.000, (...)
[Shot 2] At 00:03.000, (...)

overall_soundscape:
(...). Shot 1: (...). Shot 2: (...). Voice only from (S1); no other dialogue.

non_diegetic_music:
N/A
```

> 详尽度判断标准：**把这一块连同本段 Picture 图一起复制出去，不借助文档任何其他内容，就能直接生成出符合要求的连续画面。**
>
> 字段之间不插说明文字、不加小标题、不写“同上”。**六段式是一个字符串**，拆开就失效。

### 五、本段负面词

锁定与风格已写进 `subject_definitions` 与 `detailed_description`，此处只放负面词，供工作流的负面节点使用。无负面节点则写“本工作流无负面节点”。

```text
换脸、面部漂移、服装漂移、发型改变、多余人物、错误的人说话、穿模、比例失衡、文字、字幕、水印、logo、插画感、3D渲染感、过曝、塑料质感
```

> 负面词按题材调整：古典加“现代物件、宫殿化华丽”；现代加“穿帮的旧时代元素、廉价滤镜”；科幻加“通用赛博朋克霓虹堆砌、无来源光源”。

### 六、本段故事板

**版式（每段必出两版式，各一张，依次插入）**：

- `SB-0N · table` 展示版（六区段落板：① 出场人物＋道具／② 对手戏场景／③ 空间调度／④ 分镜关键帧／⑤ 光影材质／⑥ 摄影技术，2400×2960）——给人看
- `SB-0N · raw` 模型版（**`grid_of(N)` 网格**，每格严格 16:9，全图零文字，默认 2352×1000）——给视频模型

- 图注：`SB-0N｜展示版｜P0N 六格｜时间码范围`
- 说明格位与关键帧的对应关系：`第 1 格 = 关键帧 01；第 2 格 = 关键帧 02；……`（两版格序一致，均以整张 **`grid_of(N)`** 网格为基准，6 格时读序 R1C1→R2C3）

> 展示版已含全部文字（镜号、景别、画面描述、台词、时长运镜），文档中不重复抄写，只做图注与对应说明。模型版是**给机器用的**：整张可作分镜参考，按格裁开即 6 张单帧，可直接作图生视频首帧——正因如此它没有文字，文档里也不逐格解说它。
>
> 提示词里用 `[Shot N]` 与时间码定位镜头，**不按格位指代**。镜头数与格数可以不等（**镜头数 ≤ 本段格数 N，每镜至少占一格**），用“第 X 格”指代镜头会指错。

# 排版规范

| 项目 | 规范 |
|---|---|
| 字体 | 正文中文宋体或思源宋体，标题黑体；英文与数字用同一字族的西文版本 |
| 正文 | 小四（12pt），行距 1.5 |
| 一级标题 | 第一部分／第二部分，二号，居中，另起页 |
| 二级标题 | 段落标题、角色小节、场次小节，三号，加粗 |
| 三级标题 | 关键帧条目，小四加粗 |
| 第一部分图片 | **资产卡**（角色卡／场景卡／道具卡）按页面宽度 90% 居中，**原尺寸**；图注写资产编号与出场场次 |
| 第二部分图片 | **每段自带本段用图**：角色图、场景图、道具图用长边 1600px 压缩版（控制文档体积，此处的图即本资产卡或故事板源图），故事板满版宽度居中；图注写 `Picture N｜资产编号｜用途`（故事板图注写 `SB-0N｜展示版／模型版`） |
| 表格 | 仅在需要横向量化对比时使用，不把提示词做成表格 |
| 页眉页脚 | 页眉写篇名，页脚写页码 |
| 分页 | 第一部分与第二部分之间强制分页；每个段落之间强制分页 |
