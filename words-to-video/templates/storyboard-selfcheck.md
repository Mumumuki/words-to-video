# 第十二步 c 段｜故事板出图自检

- 项目：
- 版本：SB-CHECK-v4
- 触发：**第一次拼版之后、提交 `生产包确认` 之前**，必须完整过一遍
- 对象：每段**两版式两张**整图（`table` 六区段落板 / `raw` 零文字网格），均由 N 张无字 cells 经脚本合成
- 上游：`templates/storyboard-prompt-craft.md`（12-a 打磨结果）、`storyboard-style-anchor.md`（六区几何与文字规范）

> 自检结论只在对话中汇报，不写进交付文档（文档不放校验报告）。未通过的不提交确认。

## 一、为什么单列这一步

排版与画面是两套风险：排版问题（格数、比例、均分、三栏是否压边）靠眼睛看不出来，量一下就知道；画面问题（造型漂移、空间重置、越轴）肉眼要逐格对，但整张重出会引入新的随机错误。所以两类分开处理，处理动作也不同。

改由脚本合成之后，**风险的重心变了**：文字与几何不再靠模型，A 类基本一次就过；真正要盯的是 ① 区贴图（去背干不干净、多人等高）

和 N 格的画面一致性——N 格是分次生成的，最怕 N 张画风各异。

`raw` 版另有两项**硬指标**——每格必须严格 16:9（否则裁出来的单帧当不了首帧）、全图必须零文字（否则文字会被生成进视频）。这两条不过，模型版就等于废图。

## 二、A 类｜几何项（用脚本量测，不要目测）

| # | 检查项 | 合格标准 |
|---|---|---|
| A1 | N 格互不雷同 | 每段 N 个关键帧（N=2–6，默认 6），无空格、无第 N+1 格；两版覆盖同一 N 格（两版网格由 `grid_of(N)` 决定，6 格时为 3 列 × 2 行，读序 R1C1→R2C3，第 i 格对第 i 格）；**N 格格心两两比色差 ≥12**，以防同一构图被复制到多格（`verify_storyboard.py` 直接出数） |
| A2 | 格内比例 | `raw` **每格严格 16:9**（±0.5%，硬指标：裁出的单帧要直接当首帧）；`table` 每格画面区 725×408 亦为 16:9（±1%） |
| A3 | 网格 / 三栏结构 | `raw` 与 `table` ④ 区均按 `grid_of(N)` 排布（6 格时为 3 列 × 2 行），格间留白一致、网格居中且四边有安全边；`table` ① ② ③ 三栏宽度为 640 / 900 / 636 且**互不压边** |
| A4 | 画幅 | `table` **2400×2960**（±2%）；`raw` 宽 2352、高随格数扩展（6 格时为 2352×1000，≈2.35:1，±5%） |
| A5 | cells 齐全 | `cells/` 下 N 张源图齐全，命名 `P0N-KF01`…`P0N-KF0N`，与格位一一对应，**严格 16:9 且尺寸一致、不带任何文字**。这是主流程必出项，不是可选项 |
| A6 | 题头带与零文字 | `table`：顶部为**深色通栏题头**（左情节号＋篇名、右四组参数），非浅色带；页脚含风格卡版本与套次。`raw`：**无页眉页脚、全图零文字**，顶部应为纯色背景带（标准差低） |
| A7 | ④ 两行画面带 | `table` 两道画面带（6 格时即 3 列 × 2 行网格的两行）实测存在：顶边落在 `y=1104` 与 `y=1104+620+40`（±2% 画高，格数变化时按 `grid_of(N)` 动态位置），带高 ≈408（±10%）。这一项同时校验了 ④ 区没有被上下挤压。`raw` 没有六区分带，**不评此项** |

**跑法**：两版各用脚本量测（脚本不可用时按上表用图像工具实测同一批数值）：

```bash
# 展示版（六区段落板）
python scripts/verify_storyboard.py --image <故事板-table.png> --layout table

# 模型版（给视频模型）：按 grid_of(N) 网格 + 每格 16:9 + 零文字无页眉
python scripts/verify_storyboard.py --image <故事板-raw.png> --layout raw

# 核对 A5 源图（两版都建议带）
python scripts/verify_storyboard.py --image <故事板-raw.png> --layout raw --cells cells --prefix P01
```

脚本按 A1 → A7 顺序输出每项实测值与 PASS / FAIL，末尾给出汇总；退出码 0 为全通过。
**A1–A7 共 7 项（`table`）／A1–A6 共 6 项（`raw`，不评 A7）。** 六区各带的高度由脚本常量直接决定（2400×2960 画布上逐区绘制，不存在「模型画歪」），A4 管整张画幅、A7 管 ④ 两行带的位置，两者合起来足以发现「某区被挤压」这类错误。
需带 Pillow 的解释器运行（Windows 下若默认 python 无 PIL，用 venv 里的 python.exe）。
注意 **A6 脚本只测条带存在性/均匀性**（`table` 判顶部是否为深色带、`raw` 判顶部是否为纯色无文字），条带里的文字内容是否写全仍需人工按上表核对。

`--crop-to` 是**可选**工具，在这里有正经营生：`raw` 版的价值就是裁帧。要单独引用某一格、或把 6 帧交给图生视频模型时，用它按几何裁出单帧——`raw` 每格严格 16:9 且格间有安全边，裁出来不会带进邻格残边。`cells/` 里本来就有源图，反裁只会掉画质。

## 三、B 类｜视觉项（逐格对照，逐项打勾）

| # | 检查项 | 看什么 |
|---|---|---|
| B1 | 文字内容正确性 | 关键帧号 01→0N 连续、无重号跳号；六区标题、姓名、编号、台词、时间码与数据 JSON 一致（文字由脚本绘制，不会写错字，但要核**内容对不对**） |
| B2 | 六区文字完整 | ① 姓名／编号／作用短语三组齐全（作用短语至多 4 行）；② 场景编号到子视角＋说明；③ 有站位说明（单人静态段同样有）；④ 每格四层信息齐全；⑤ 四块标签；⑥ 八到十项。文字未溢出、未被截断，同级字号一致 |
| B3 | 文字不压画面 | 除 ④ 编号与时间码角标（白字深描边）外，**任何文字不叠在画面之上**；`raw` 画面区内除画面本身外无任何元素 |
| B4 | 造型一致性 | 与角色图同造型：服装、发型、体型、面部一致；**下装与足服完整，无赤身** |
| B5 | 空间一致性 | 与 `场景01-V01/V02` 结构一致：墙体边界、门窗朝向、家具位置未重置 |
| B6 | 光线逻辑 | 光源方向、色温、明暗比跨格连续；无昼夜或冷暖突变，要变须有叙事理由 |
| B7 | 轴线与视线 | 无越轴；A 看画左则被看者在画右，视线方向匹配 |
| B8 | 运镜连贯 | 推近、环绕、过肩、正反打在格间连续；背景位移合理，无空间跳变 |
| B9 | 新信息与 30 度 | 相邻格不复制构图；同主体同景别的相邻机位夹角 ≥30° |
| B10 | 道具 | 形制、材质与道具图一致；无凭空多出的道具，也应出现的道具不漏 |
| B11 | 人物与肢体 | 无多余人物、无多余肢体；人数与分镜表一致 |
| B12 | 时代与风格 | 无现代元素；无插画感、3D 渲染感、过曝、影楼磨皮等风格偏移 |
| B13 | 构图完整性 | 主体与关键元素未被压边或裁切掉 |
| B14 | 水印 | 记录水印位置（提示词去不掉，供后期裁切参考），不谎称已去除 |
| B15 | 格位映射 | **以整张 `grid_of(N)` 网格为基准**核对：格位顺序与关键帧号、分镜表登记完全一致；抽查 `table` 第 i 格与 `raw` 第 i 格是否为同一关键帧 |
| B16 | 跨段衔接 | 上段末格与下段首格在时间、造型、光线上接得上 |
| B17 | ①区贴图 | **无白底残留**（人物／道具周围不应出现浅色方块边界）；**人像一律半身**（单人也要半身，不该出现全身像）；**多人时人像等高、底部对齐、间距均匀**；姓名前 A/B/C 与 ③ 区方位点**一一对应**；道具在多人时已退成文字 |
| B18 | N 格一致性 | N 格是分次生成的：风格卡质感、颗粒、锐度、色温是否一致；有没有某一格明显像另一部片 |
| B19 | **格镜对齐（硬项）** | 把 N 格时间码与第八步 `[Shot N]` 时间码**并列摊开**核对，五条同时成立才算过：① 首格起于**本段起始时间码**（首段为 `00:00.000`；`P02` 起是它自己的起点，不是零）；② 末格止于本段结束；③ 相邻格首尾相接，无空档、无重叠；④ **每格完整落在同一镜内**——任一镜头切换点落在某格区间内部即不合格；⑤ **每镜至少一格**（等价于本段镜头数 ≤N）。任一条不成立，回退第七步重排时间码，**不在故事板上改格凑数、不在提示词里补镜头迁就**。故事板上不写 Shot 号，两者只靠时间码对齐 |
| B20 | 与六段式是否打架 | 把故事板某一格与第八步对应时间段落的描述对照：人物位置、服装、光位、动作是否一致。不一致时**以已确认的第八步为准改格**，不能反过来改提示词去迁就一张画错的图 |

## 四、发现问题怎么处理

| 问题类别 | 处理动作 | 禁止 |
|---|---|---|
| A 类任一不过 | 改数据或脚本常量重新拼版；仅裁切错则重排 | 不回退分镜，不改关键帧结构 |
| `raw` 出现文字 / 格内非 16:9 | **必须处理**：查 cells 是否带字、格宽是否为 16 整数倍；不得将就使用 | 不带着文字或错比例去裁帧——裁出来就是废帧 |
| B1 / B2 文字类 | **改数据 JSON 重排**（文字由脚本绘制，不应手工修图） | 不在导出图上涂改文字 |
| B3 文字压画面 | 改脚本坐标重排 | 不局部擦除了事——说明版式算错了 |
| B4–B13、B18 画面内容类 | **只重出对应那一张 cell**，其余五格不动，再重新拼版 | 不整张重出——会引入新的随机错误，也破坏六格一致性 |
| B17 ①区贴图 | 检查 `crop` 是否切进信息表、资产图是否纯色底；必要时回退 S9/S10 重出资产图 | 不放宽去背要求硬贴 |
| B15 映射错 | 修正映射表与文件命名后重新核对 | 不靠口头说明掩盖编号错位 |
| B19 格镜不对齐 | 切点落在格内、有空档或重叠、某镜一格都没有——**回退第七步重排时间码或拆段**，只重出受影响的格 | 不在故事板上改格凑数，也不在提示词里补一个镜头去迁就 |
| 缺帧 / 多帧 / 顺序错 | 停止修补，回退第七步重新确定关键帧 | 不在故事板阶段增删关键帧 |
