# words-to-video

> 从一句话想法或一段原文出发，一路推进到「视频生成前的一切准备」——剧本、设定、资产、分镜、提示词、故事板，直到可以直接粘进 ComfyUI 的填表包。
>
> 一个面向 AI 视频生产的**执行型 Agent Skill**，不是提示词合集。

## 它解决什么问题

AI 视频生成的瓶颈从来不在「按生成键」，而在**按下去之前的那堆准备工作**：故事立不立得住、人物是不是纸片人、角色和场景能不能跨镜头保持一致、9 个参考图槽位怎么排、段与段之间怎么接得上。

这些工作散落在编剧、美术、分镜、提示词工程四个领域，通常要靠人来回协调。`words-to-video` 把这条链路**固化成一条有门禁的流水线**：你只需要给起点、在四个关键节点拍板，其余由 Agent 连续推进。

**一句话 → 可执行的生产包。**

## 核心特性

### 1. 题材中立，四轴定位

不是「古文转视频」，也不预设任何题材。当代现实、历史年代、未来科幻、架空幻想、神话志怪、古典诗文——统一用**四轴**定位：

| 轴      | 内容                        |
| ------ | ------------------------- |
| ① 时代世界 | 当代 / 近代 / 古代 / 未来 / 架空    |
| ② 类型片  | 生活流 / 悬疑 / 爱情 / 科幻 / 武侠 … |
| ③ 地域   | 决定空间、气候、建筑与人种气质           |
| ④ 调性   | 冷峻 / 温暖 / 荒诞 / 压抑 …       |

题材未定时，它会主动给出 **2–3 个落在不同轴位**的方案让你选，而不是默认挑最顺手的那个。

### 2. 破题优先：核心戏剧动作

开工第一件事不是处理原文，而是确立故事的「核」——**核心戏剧动作 ＝ 谁想要什么 ＋ 被什么挡住 ＋ 代价是什么**。

来源形态（`adaptation` / `original` / `hybrid`）只在 S0 登记一次，**不作流程路由**：改编与原创走同一条故事开发流程。改编项目的「忠于原作」落成边界清单与不可改变项，而不是让剧情开发退化成复述原文。

全部产出带四标签标注：`[来源]` / `[设定]` / `[推断]` / `[创作]`。

### 3. 四道门，但只有最后一道要你拍板

十五道内部工序，**你只在 G4 停下一次**：

| 门      | 性质       | 覆盖            | 锁定什么                       |
| ------ | -------- | ------------- | -------------------------- |
| **G1** | 检查点（不停）  | S0–S4         | 来源、题材方向、世界观、剧本、角色/场景/道具设定  |
| **G2** | 检查点（不停）  | S5–S6         | 六维风格卡、导演交接包（含核心视听手法）       |
| **G3** | 检查点（不停）  | S7–S8 + 提示词草稿 | 分镜表、语速、槽位分配、H3 六段式提示词      |
| **G4** | **唯一硬门** | S9–S14        | 资产图、故事板、校验、Word、填表包        |

G1–G3 的产出照常写定、照常展示、照常作为下一步的输入，**只是不中断流程去等你喊"通过"**——你随时可以就任何一处提修改，按回退矩阵回退；没提就默认接受，继续跑。S9 生图前还有一次**成本告知**（只报图片总数与预估消耗，不是门）。G4 之前一切都是草稿，「跳过确认」「直接提交」**不算通过**。

### 4. 上游剧本工艺：一句话也能长成超级剧本

前期四步（S0–S3）直接以**山音编剧工作流的短片八步**为主体（破题与核心动作 → 梗概草稿 → 人物深度与弧光 → 前史与世界观 → 结构大纲 → 场景拆解 → 场景写作 → 剧本医生），本技能只按"哪一步需要你看到结果"把它并成四道内部工序。不靠感觉，靠方法：

- **构思武器库**（内部使用，不展示给你）——五选题路径 + 概念锻造工作流 + 概念组合五法（含操作步骤）+ 概念结构五型 + How-to-Tell 五法 + 跨格式技法借鉴地图，把「雨夜外卖员在桥上停了很久」锐化成带结构的 logline
- **短片默认四幕骨架**——起因 / 发展（障碍 1、障碍 2、中点与一切尽失）/ 高潮 / 结局；需要更重的骨架时再升级到 STC 15 拍 / Story Circle / McKee 价值转变 / 内在节拍
- **人物深度**——want/need/弧光/阻力/秘密，加 Ghost / Lie / Flaw / 矛盾性
- **世界观三层**——表层规则 → 运行逻辑 → 底层真相，配信息释放时间表（科幻利器）
- **剧本医生**——产出后强制诊断：价值转变、鸿沟、危机选择、无效情节、伏笔审计、群像功能、节奏、开场质量
- **写作红线**——禁心理描写、禁解释性台词、动作即潜台词、冰山对话

### 5. 角色不是形容词堆出来的

「轻佻的男性」「清冷的女主」这类模糊描述会被**拆成维度名词**再落地：

- 形容词 → 名词化（`疲惫` → 眼周阴影 / 气色 / 头发打理程度的具体项）
- 三层标注：身份 / 造型 / 状态
- 不完美与生活痕迹：老茧、晒痕、饺子耳、指节
- 刚柔光谱定位 + 强制「留一处反向」
- 形容词残留检查

配套 **多样化外貌服饰库**：47 种服装风格、时代与类型（含赛博朋克 / 太空科幻 / 末日废土 / 中世纪奇幻）、人群与身份（含职业制服）、9 份维度名词词库。**古代形制库已降级为选项之一**，只在历史题材加载。

### 6. 生产工程：一致性是设计出来的

- **核心视听手法** —— S6 从视听手法库选 1–2 种（镜头语言 / 剪辑时间 / 画面构成 / 声音 / 界面媒介五类），写清为什么契合概念、用在哪些段落、怎么递进，S7 落到景别/角度/运镜/衔接/音效字段，不在故事板阶段临时发挥
- **视觉连续性锁** —— 角色/场景/道具一经定稿，跨镜头不得漂移
- **段间承接链** —— 上一段末帧作下一段首帧参考，为长视频留接口
- **说话镜头锁人** —— 谁说话镜头给谁，不漂
- **语速核算** —— 台词字数反推时长，写不下的改分镜，不改台词
- **资产卡一整张图 = 一段提示词** —— 角色卡五区、场景卡左二右四、道具卡四宫格
- **Picture 编号整集统一** —— 资产的身份证，填表包里一个字不能错

### 7. 默认不替你按生成键

产出**填表包**（执行单），由你手动运行。

可选 **S15 自动提交**：G4 之后、你**显式同意**、且已配置适配器时，经 `delivery/` 提交到平台。配置驱动、换平台不改脚本，凭据走环境变量不落盘。没拿到同意时只输出执行计划，绝不碰接口。

## 快速开始

### 安装

把整个目录放进你的 Agent 技能目录即可（如 `~/.workbuddy/skills/words-to-video`、Claude Code 的 `.claude/skills/`、或任意支持 `SKILL.md` 的 Agent）。

### 使用

直接给一个起点，措辞不限：

```
把"雨夜，一个外卖员在桥上停了很久"做成 60 秒剧情短片，现代，当代县城感觉。
```

```
把《氓》改成 90 秒短片。
```

```
科幻：一个维修工在空间站发现了一盆不该存在的植物。
```

第一句话里尽量带上：

- **来源** —— 一句话 / 原文 / 大纲 / 已有剧本
- **时长** —— 目标多少秒（默认按 10–15 秒一段规划）
- **题材** —— 不说的话它会给方案让你选
- **类型** —— `剧情演绎`（默认）或 `MV`

然后你只需要在四个门喊口令。

## 全流程

```
S0  破题与核心动作（项目定义 + 戏剧动作）   ┐
S1  梗概草稿（一段话走向与气质 + 容量判断） │
S2  人物深度与弧光 + 前史与世界观           ├ G1 故事定稿（检查点·不停）
S3  结构大纲 → 场景拆解 → 场景写作 → 剧本医生│
S4  角色/场景/道具资产设定与编号锁定        ┘
S5  风格定稿（六维风格卡）                  ┐ G2 视觉定稿（检查点·不停）
S6  导演交接包（编号占位，此时未生图）      ┘
S7  段落切分与分镜表                       ┐
S8  H3 六段式提示词 + 资产提示词草稿       ┘ G3 分镜定稿（检查点·不停）
S9–S11 资产图生成（角色卡/场景卡/道具卡）
S12 故事板（关键帧 → 出图拼版 → 自检）
S13 一致性校验 + Word 交付文档
S14 ComfyUI 填表包（只产出，不提交）
─────────────────────────────────────
S15 可选：经 delivery/ 自动提交（需显式同意）
```

---

## 你会拿到什么

1. **Word 交付文档**（.docx）—— 第一部分剧本总览（含角色/场景/道具卡），第二部分分镜执行
2. **ComfyUI 填表包**（`package/`）—— 每段 `prompt.txt` + 裁好的参考图 `refs/` + 段间承接帧 `handoff/` + 映射表 + 参数清单 + 填表单
3. **资产卡与故事板图片** —— 角色/场景/道具卡各为整图；故事板每套两张（`table` 给人看 / `raw` 给模型）

## 设计原则

| 原则          | 说明                                                                                   |
| ----------- | ------------------------------------------------------------------------------------ |
| **工具无关**    | 面向 ComfyUI + MiniMax，但平台知识隔离在 `references/platforms/` 与 `delivery/adapters/`，换平台只换配置 |
| **门禁而非口令**  | 只有 G4 一道硬门；G1–G3 是检查点，展示即继续。门内自由迭代，Agent 只能建议下一门，不能替你确认                                  |
| **编号优先于图片** | 导演阶段用编号占位工作，不依赖尚未生成的资产图——避免循环依赖                                                      |
| **上游只喂养文字** | 新增的人物深度字段不进入资产卡 schema；下游卡/板结构稳定不受上游迭代影响                                             |
| **回退有矩阵**   | 改了上游必须回退下游，SKILL.md 里有完整的回退对照表                                                       |
| **输出前自检**   | 铁律级纪律：带已知问题不出；四张自检清单覆盖概念/人物/结构/场景写作                                                  |

## 可选：自动提交（S15）

```bash
# 1. 复制配置并填端点
cp delivery/config.example.json delivery/config.json

# 2. 先看执行计划（不碰接口）
python delivery/submit.py --package ./package --adapter comfyui_local --dry-run

# 3. 确认无误后，显式同意才提交
python delivery/submit.py --package ./package --adapter comfyui_local --consent
```

适配器：`comfyui_local`（本机 ComfyUI `/prompt` API）、`cloud_minimax`（云端骨架）。换平台只需新增一个适配器 + 改 config，主脚本不动。
